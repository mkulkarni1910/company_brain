# Conversation History (persistent) — Design Spec

**Date:** 2026-06-01
**Status:** Approved (brainstorming)
**Supersedes:** the Redis-backed question-only History (`HistoryStore`, `/history`, tag `history-discover-v1`). That code stays in the repo but is no longer written to or surfaced.

## Goal

Turn History into a **persistent, ChatGPT-style conversation history**. Every Ask session is stored as a multi-turn **conversation** (question + grounded answer per turn) in **Cosmos DB (Gremlin)**. History lists conversations; clicking one **re-opens the whole saved thread** (instant replay, no re-run).

## Decisions (locked)
- Granularity: **full multi-turn conversations** (not per-Q&A).
- Re-open: **show the saved answers instantly** (accurate record; may be stale if corpus changed).
- Store: **Cosmos Gremlin** — a new `conversations` graph container in the existing `brain` database (partition key `/tenant_id`), reusing the account + key auth that the People graph already uses. Durable (unlike the Redis cache).
- Include a **"New chat"** control in the Ask view to start a fresh conversation.
- The search **AI-Overview** call (which also hits `/query`) must NOT be logged — only the Ask chat is.

## Architecture

```
Ask chat ──(/query with conversation_id)──> append turn (q + answer) to Cosmos conversation
History  ──GET /conversations──────────────> recency-ordered summaries (title, updated_at, turn_count)
open one ──GET /conversations/{id}─────────> full thread → replayed in the Ask view
```

The conversation_id is generated by the client per Ask thread; sending it (or not) on `/query` is exactly what separates "logged chat" from "unlogged search overview".

## Cosmos modelling

New container: `az cosmosdb gremlin graph create -a cbrain-lokesh-cosmos -g rg-company-brain-dev -d brain -n conversations --partition-key-path /tenant_id` (controller step).

Vertex label `conversation`, properties:
- `conv_id` (client uuid), `tenant_id` (partition key), `user_id`
- `title` (first question, ≤80 chars), `created_at`, `updated_at` (ISO strings — lexicographic = chronological for ordering)
- `turn_count` (int), `turns_json` (string: JSON array of `{q, a:{text, citations}, ts}`, capped at the last 50 turns)

## Backend — `app/conversations/`

**`store.py` — `ConversationStore`** (own gremlinpython `client.Client`, mirroring `PeopleGraphClient`'s construction but `colls/{conversations_graph}`; key auth from settings). All methods best-effort (swallow Gremlin errors; never break `/query`).
- `append(*, user, conversation_id, query, answer)`: read existing `turns_json` (if any), append the new turn, cap at 50, then upsert via the Cosmos `coalesce(unfold(), addV(...))` idiom — `title`/`created_at` set only on create; `updated_at`/`turn_count`/`turns_json` set every time.
- `list(*, user, limit=100) -> list[ConversationSummary]`: `g.V().has('conversation','tenant_id',tid).has('user_id',uid).order().by('updated_at', decr).limit(N).project('conv_id','title','updated_at','turn_count')…`.
- `get(*, user, conversation_id) -> Conversation | None`: `valueMap` → parse `turns_json` into turns; `None` if not found.

**`app/domain/conversation.py`**
```python
class ConversationTurn(BaseModel):
    query: str
    answer: Answer            # text + citations (debug dropped on store)
    ts: datetime
class ConversationSummary(BaseModel):
    id: str
    title: str
    updated_at: datetime
    turn_count: int
class Conversation(BaseModel):
    id: str
    title: str
    created_at: datetime | None = None
    updated_at: datetime
    turns: list[ConversationTurn]
```

**Endpoints — `app/api/conversations.py`**
- `GET /conversations` → `resolve_user` → `store.list(...)` (→ `[]` if store unavailable).
- `GET /conversations/{conversation_id}` → `resolve_user` → `store.get(...)` (→ 404 if not found / unavailable).

**`/query` change (`app/api/query.py`)**: `QueryRequest` gains `conversation_id: str | None = None`. After the answer is produced, if `conversation_id` is present and the store exists, `await conversation_store.append(...)` (best-effort). The old `HistoryStore.add(...)` write is removed.

**Wiring**: `ConversationStore` constructed in `main.py` lifespan; tolerant `get_conversation_store` in `deps.py`; routers included; settings gain `cosmos_gremlin_conversations_graph: str = "conversations"`. The store is optional — if Cosmos isn't configured, `/conversations` degrades to empty and `/query` simply doesn't log.

## ACL / privacy
Conversations are filtered by `user_id` (within the tenant partition) on every read — a user only ever sees their own. Stored answers were already ACL-trimmed at generation time.

## Frontend

**`web/lib/api.ts`**
- `postQuery(query, conversationId?)` — include `conversation_id` when given. (The SearchView overview call keeps calling `postQuery(query)` with no id → not logged.)
- `getConversations() -> ConversationSummary[]`, `getConversation(id) -> Conversation | null`; matching types.

**`web/components/Chat.tsx`**
- `Chat` holds `conversationId` (`crypto.randomUUID()` on mount). `ask()` passes it to `postQuery`.
- **"New chat"** button (left rail, under the brand/nav) → new uuid + clear `turns` + switch to Ask.
- **History view → ConversationsView**: `getConversations()` → list rows (title, `relTime(updated_at)`, "N turns"). Click → `getConversation(id)` → map turns to the existing `Turn` shape (`{id, query, answer, loading:false}`), `setTurns(...)`, `setConversationId(id)`, `setView("ask")` — replaying the whole thread. Continuing the chat appends to the same conversation.
- Empty state when there are no conversations.

## Error handling / degradation
- `append` and all store reads are best-effort: Gremlin/Cosmos failure never 500s `/query`, `/conversations` returns `[]`, `/conversations/{id}` returns 404.
- Frontend `getConversations`/`getConversation` return `[]`/`null` on any error.

## Testing (TDD)
- `ConversationStore` (fake `submit`, mirroring `test_resolve_people`): `append` builds the coalesce upsert with the new turn + capped at 50; `list` parses + orders; `get` parses `turns_json` into turns; all degrade to `[]`/`None` on error.
- Endpoints: `/conversations` + `/conversations/{id}` require auth (401), return shapes, degrade when store unavailable.
- `/query`: appends a turn only when `conversation_id` is present (and not otherwise).
- Frontend smoke: new-chat resets; opening a conversation replays turns; sending continues the same conversation.

## Out of scope / deferred
- Conversation rename/delete, search within history, sharing, pagination beyond the most recent 100, cross-device real-time sync. The old `/history` + `HistoryStore` stay dormant (not deleted) to avoid churn.
