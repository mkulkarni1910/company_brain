Building AI agents is becoming easy. Trusting them with real work is the hard part. We turn the know-how in people's heads into playbooks the AI runs — your rules, a person approving anything risky, every action logged.

Microsoft Build AI
★ Priority — Intelligence Design

Smart by construction

  • Playbook engine: the same shape for any task — When → Check → Stop → Do → Record.
  • Climbs the ladder past Find/Plan to Do and Stay in control — where the value is.
  • Hybrid retrieval fused across Content · People · Activity; personalized per persona.
  • Grounded generation with citations; stops if unsure rather than guessing.
  • Two-tier model routing: a fast model acknowledges instantly ("On it…"), the strong model answers — lower perceived latency.
  • Gemini today, Azure OpenAI–ready; plugs into Copilot Studio & Foundry.
★ Priority — System Architecture & Engineering Quality

Production-grade, safe to allow

  • Known identity on every surface (Entra) + double-enforcement ACLs, fail-closed.
  • Human approval for risky moves; a full record of who/what/which-rule/when.
  • Strict module boundaries — each component a swappable interface.
  • Versioned like code: AI drafts → owner reviews → human approves → live → rollback anytime.
  • Eval harness + pytest gate every change; OpenTelemetry → Azure Monitor.

Backend modules — substrateos-api/app/

orchestrator/

Semantic Kernel + QueryPlanner — sequences the gather-facts steps; Live Fetch vs cache.

skills/ · workflows/

Playbook catalog/router + the When→Check→Stop→Do→Record engine and run store. Flows: RefundFlow · ApprovalFlow · GithubFlow (github_pr.py + github_engine.py PrDraftEngine).

retrieval/

AISearchClient + HybridRetriever — BM25 + vector over the content index.

people/

PeopleGraphClient + PeopleProximity over Cosmos Gremlin.

activity/

ActivitySignal + ActivityStore — engagement scores from ADX.

ranking/

PersonalizedRanker — RRF fusion + weighted multi-signal, per persona.

generation/

Azure OpenAI + Gemini clients — grounded answers with citations.

acl/

ACLStore — double-enforcement; query-time recheck, fail-closed on outage.

live_fetch/

MSGraphSearchFetcher — on-behalf-of Graph for "right now" facts.

conversations/

ConversationStore + memory — trimmed history into grounded prompts (web · Slack · Teams); history-carrying answers bypass the answer cache.

ingest/ · connectors/

chunk→embed→ACL-stamp→index; SharePoint/Outlook/Teams connectors. GitHub action connector: github.py (REST client) + github_store.py (config · per-user tokens · OAuth states).

discover/ · search/ · history/

Discover, search, and history services behind the nav surfaces.

cache/ · tokens/ · metrics/

Redis answer cache · PAT token accounting · metrics store.

directory/

User Directory — joins Slack and Entra ID identities on email. DirectoryStore: Redis-backed (keys directory:user:{email}, directory:slack:{id}) + in-process fallback. DirectorySync: daily pull of Slack users.list + Graph users/$expand=manager + Managers / Support Agent group members; fail-soft merge. DirectoryService: request-time resolve(email) — cache-first, live Slack+Graph write-through fallback. Roles: manager · agent · customer.
