Architecture · Productivity & Teamwork Reimagined

Building AI agents is becoming easy. Trusting them with real work is the hard part. We turn the know-how in people's heads into playbooks the AI runs — your rules, a person approving anything risky, every action logged.

Microsoft Build AI
★ Priority — Intelligence Design

Smart by construction

  • Playbook engine: the same shape for any task — When → Check → Stop → Do → Record.
  • Climbs the ladder past Find/Plan to Do and Stay in control — where the value is.
  • Hybrid retrieval fused across Content · People · Activity; personalized per persona.
  • Grounded generation with citations; stops if unsure rather than guessing.
  • Plain-English authoring: an SME describes a rule, one LLM call structures it into the playbook form — authoring by anyone, behind human gates.
  • Two-tier model routing: a fast model acknowledges instantly ("On it…"), the strong model answers — lower perceived latency.
  • Gemini today, Azure OpenAI–ready; plugs into Copilot Studio & Foundry.
★ Priority — System Architecture & Engineering Quality

Production-grade, safe to allow

  • Known identity on every surface (Entra) + double-enforcement ACLs, fail-closed.
  • Deterministic policy-as-code guardrail (app/policy/ — never the model, always fail-closed).
  • Human approval for risky moves; a full record of who/what/which-rule/when.
  • Strict module boundaries — each component a swappable interface.
  • Versioned like code: AI drafts → owner reviews → human approves → live → rollback anytime.
  • Eval harness + pytest gate every change; OpenTelemetry → Azure Monitor.

Backend modules — substrateos-api/app/

orchestrator/

Semantic Kernel + QueryPlanner — sequences the gather-facts steps; Live Fetch vs cache.

skills/ · workflows/

Playbook catalog/router + the When→Check→Stop→Do→Record engine and run store. Flows: RefundFlow · ApprovalFlow · GithubFlow (github_pr.py + github_engine.py PrDraftEngine) · SkillPublishFlow (skill_publish.py).

skills/drafter.py · api/studio.py · api/_sme_guard.py

Skill Studio — SMEs author skills in plain English. _sme_guard.py: Entra Finance SME group (ENTRA_SME_GROUP; claims or cached Graph member lookup, fail-closed; admin ⊃ SME). drafter.py SkillDrafter: one LLM call → a SkillCreate draft. studio.py: draft / submit / resubmit / withdraw / my-submissions. Submission = a skill_publish run; the live SkillStore is written only on approval.

people/

PeopleGraphClient + PeopleProximity over Cosmos Gremlin.

PersonalizedRanker — RRF fusion + weighted multi-signal, per persona.

generation/

Azure OpenAI + Gemini clients — grounded answers with citations.

acl/

ACLStore — double-enforcement; query-time recheck, fail-closed on outage.

live_fetch/

MSGraphSearchFetcher — on-behalf-of Graph for "right now" facts.

conversations/

ConversationStore + memory — trimmed history into grounded prompts (web · Slack · Teams); history-carrying answers bypass the answer cache.

policy/

PolicyEngine — deterministic guardrail, never the model. Loads + validates policies/*.yaml (PyYAML, via policy/store.py). Fail-closed: any unknown or breached rule blocks the run. Refund policy: policies/refund.v1.yaml.

PyYAMLpolicies/refund.v1.yaml

approvals/

ApprovalService — durable, identity-bound approval gate. PendingApproval persisted in Redis; survives restarts. Only the role-authorized Entra manager may approve; hard-denies clicks from unrecorded approvers.

Redisidentity-bound

audit/

AuditLog — typed, append-only audit trail. Every action actor-stamped (who asked, which rule, who approved, what changed, when). Queryable per run from the Admin Runs view.

ingest/ · connectors/

chunk→embed→ACL-stamp→index; SharePoint/Outlook/Teams connectors. GitHub action connector: github.py (REST client) + github_store.py (config · per-user tokens · OAuth states). Act connectors: connectors/act/stripe_mock.py (seeded/mocked Stripe refund).

discover/ · search/ · history/

Discover, search, and history services behind the nav surfaces.

cache/ · tokens/ · metrics/

Redis answer cache · PAT token accounting · metrics store.

directory/

User Directory — joins Slack and Entra ID identities on email. DirectoryStore: Redis-backed (keys directory:user:{email}, directory:slack:{id}) + in-process fallback. DirectorySync: daily pull of Slack users.list + Graph users/$expand=manager + Managers / Support Agent group members; fail-soft merge. DirectoryService: request-time resolve(email) — cache-first, live Slack+Graph write-through fallback. Roles: manager · agent · customer.

Cross-cutting

Security — safe to allow

Known identity (Entra) on every surface · double-enforcement ACLs (index stamp + query recheck, fail-closed) · admin console restricted to the Entra Admin group (fail-closed Graph check) · deterministic policy-as-code guardrail (app/policy/ — never the model) · human approval for risky moves · stops if unsure.

Audit — a full record

Every action logged: who asked · which rule applied · who approved · what changed · when. AuditLog (app/audit/): typed, append-only, actor-stamped, queryable per run. RunStore + metrics.

Observability

structlog + OpenTelemetry → Azure Monitor / App Insights. One trace per request, ranking signals as span attributes.

Quality gates

pytest suite + eval harness (golden Q&A recall/MRR). Frontend typecheck + lint + build before ship.

Identity flow

DefaultAzureCredential → user-assigned managed identity in cloud; OBO to Microsoft Graph for Live Fetch.
